# SITI 申請策略深度指南

> 本文件基於近 3 年（112-114 年）354 件通過案例的統計數據，提供不靠直覺、靠數據的申請策略。

---

## 第一章：選對計畫（最重要的決策）

### 依公司階段選計畫

```
設立未滿 1 年
  → 唯一選擇：創業補助（100萬）
  → 策略：申請滿額，計畫聚焦「MVP + 首批客戶」

設立滿 1-3 年，尚未有投資人
  → 主力：創新研發（最高 500萬）
  → 配合：等主題式研發梯次公告（200萬，幾乎必給滿額）
  → 如有品牌需求：先研發 → 結案 → 接品牌

設立滿 1-8 年，已有創投/天使投資 ≥ 500萬
  → 優先評估：新創拔尖（最高 1,500萬，三階段）
  → 但要等梯次，且投資人願意寫推薦書是關鍵門檻

設立超過 8 年的成熟企業
  → 創新研發（仍可申請，沒有年限上限）
  → 品牌建立（若有品牌升級需求）
  → 獎勵補貼（若正在台北市增資/擴編）

育成機構 / 天使投資人
  → 創新育成 / 天使投資 / 國際育成（各最高 300萬）
```

### 依需求類型選計畫

| 你最主要的需求 | 推薦計畫 | 備選 |
|-------------|---------|------|
| 研發新技術/產品 | 創新研發（500萬）| 主題式研發（200萬，等梯次）|
| 建立 / 升級品牌 | 品牌建立（500萬）| — |
| 剛創業，需要第一桶金 | 創業補助（100萬）| — |
| 有投資背書，需要大額補助 | 新創拔尖（1,500萬）| 創新研發（先做）|
| 驗證商業模式（不是技術）| 創新加速（300萬）| — |
| 剛設立台北辦公室 | 獎勵補貼（租金/薪資，可疊加）| 同時申請研發 |

## 第二章：金額策略（數據最反直覺的發現）

### 核心洞察：多數人嚴重低估自己能申請的金額

| 計畫 | 平均申請金額 | 上限 | 利用率 | 建議策略 |
|-----|-----------|------|-------|---------|
| 創新研發 | **198 萬** | 500 萬 | **40%** | 大膽申請 350-450 萬 |
| 創新加速 | 196 萬 | 300 萬 | 65% | 申請 250-300 萬 |
| 主題式研發 | **200 萬** | 200 萬 | **100%** | 直接申請滿額 |
| 品牌建立 | — | 500 萬 | — | 依實際需求，建議 300-400 萬 |

**創新研發補助的真實情況**：
- 近 3 年 59 件通過，平均只申請 **198 萬**，但上限是 **500 萬**
- 這表示多數人只申請了上限的 40%
- **原因**：申請人保守估計，或不知道「計畫書品質決定通過率，而非申請金額」

### 如何計算合理的申請金額

```
1. 從工作內容反推（推薦方法）
   列出所有工作項目 → 計算需要的人力（人月）× 月薪 + 外部委託費 + 工具費
   → 加總得到「需要多少錢才能做好這個計畫」
   → 這個數字的 50% = 你應該申請的補助金額

2. 常見的 500 萬計畫結構（創新研發）
   人事費：2 位工程師 × 6 萬/月 × 24 個月 × 70% 投入 = 2,016,000（補助 50% = 1,008,000）
   人事費：1 位研究員 × 5 萬/月 × 18 個月 × 100% = 900,000（補助 50% = 450,000）
   委託費：外部 AI 資料標注 = 500,000（補助 50% = 250,000）
   雲端費用（AWS/API）× 24 個月 = 300,000（補助 50% = 150,000）
   → 總補助申請 ≈ 1,858,000（184 萬）—— 還沒到 500 萬上限！
   → 意思是：如果你有更多計畫工作量，大膽加進去
```

### 什麼時候應該申請較低金額

- **你的自籌款來源無法支撐高額計畫**：100 萬補助 → 需要 100 萬自籌，要說得清楚
- **計畫期間只有 6 個月**：短期計畫自然限制可執行的工作量，別強行膨脹
- **首次申請、想先建立紀錄**：可以先申請較保守（如 150-200 萬），結案後再申請第二案時加碼

## 第三章：時序規劃（多案銜接策略）

### 規則回顧

- **同一時間只能執行 1 案**（核定通過後才能申請下一案需等結案）
- **核定不通過**：1 年內最多再申請 2 次（共 3 次機會）
- **結案 → 新申請**：最快可以在結案審核通過後立即申請

### 三年多案規劃範例

```
設立第 6 個月（還沒滿 1 年）
  → 立即申請「創業補助」（100萬，12個月計畫）
  → 計畫期間：在跑的同時準備下一案計畫書

設立第 18 個月（創業補助剛結案）
  → 立即申請「創新研發補助」（目標 350 萬，18個月計畫）
  → 同時監測主題式研發公告，若有合適主題可轉申請

設立第 36 個月（研發補助結案）
  → 若累積有投資人：評估「新創拔尖」（1,500萬）
  → 若無投資人：再申請「創新研發」（第二案，500萬上限）
  → 若需要品牌：申請「品牌建立補助」（500萬）

理想情況三年累積：100 + 350 + 500 = 950 萬補助
```

### 創業補助 → 研發補助的最佳銜接時機

```
時間點 T      公司設立
T + 6 個月    申請創業補助（應在設立未滿 12 個月前申請）
T + 18 個月   創業補助結案 → 立刻準備研發補助申請書
T + 21 個月   研發補助核定 → 開始執行
T + 39 個月   研發補助結案（18個月計畫）
T + 42 個月   第三案開始（新創拔尖 or 品牌）
```

## 第四章：計畫書品質的關鍵要素（審查委員視角）

### 什麼樣的計畫書通過率最高

根據歷史通過案例的計畫書名稱模式和金額分析，高通過率計畫書通常有：

**1. 技術具體，不模糊**

| 低通過率表達 | 高通過率表達 |
|-----------|-----------|
| 「智慧化管理系統」 | 「基於 LLM 的繁中合約條款自動分類系統（準確率 ≥ 93%）」 |
| 「創新的 AI 解決方案」 | 「結合 RAG 架構與台灣法規 fine-tuning 的智慧法律助理」 |
| 「提升效率的新平台」 | 「將中小企業月結帳時間從 8 小時壓縮到 30 分鐘的自動化系統」 |

**2. AI 關鍵字（近 3 年 22% 的通過案例含 AI）**

- 含「AI / 人工智慧 / 機器學習 / 智慧」的計畫，平均補助金額高於整體均值
- 即使核心不是 AI，只要有使用 AI 工具/方法，在計畫書中清楚描述
- 可以用的描述：「本計畫將 LLM 應用於...」「採用 AI 輔助分析...」「智慧化 XX 流程...」

**3. 台北市本位論述**

- 審查委員最在意：「這件事對台北市有什麼好處？」
- 每個段落都要帶入台北市數字或台北市關聯
- 建議在摘要頁就說：「本計畫預計服務台北市 X 家企業 / X 名市民，在台北市創造 X 個就業機會」

**4. 查核點可驗收**

- 每個查核點都要有「拿得出來的東西」
- 最好的查核點：程式碼 + 測試報告 + 用戶驗證文件
- 避免：「進度達 XX%」（不可驗收）

## 第五章：與中央補助的組合策略

### SITI × 中央 SBIR 同時申請

| 項目 | SITI 創新研發 | 中央 SBIR Phase 2 |
|-----|------------|-----------------|
| 主管機關 | 台北市政府產業發展局 | 經濟部中小及新創企業署 |
| 最高補助 | 500 萬 | 1,200 萬 |
| 補助比例 | 50% | 50% |
| 截止日 | 無（隨到隨審）| 滾動受理（分梯次）|
| 核銷限制 | 各自核銷，不得重複 | 各自核銷，不得重複 |

**可以同時申請嗎？**

✅ 可以。官方明確規定：「可與行政院（中央）同性質計畫並行申請，但**不得以相同標的重複申請，核銷費用不得重複編列**。」

**操作建議**：

```
SITI 計畫書：聚焦台北市本地應用場景（如：台北市中小企業的 X 問題）
SBIR 計畫書：聚焦全台或國際市場（台北市場只是一部分）

經費編列：人事費中的「投入比例」分開計算
  例：同一位工程師，對 SITI 投入 50%，對 SBIR 投入 40%（需留 10% 自籌）
```

> ⚠️ **最重要的規則**：同一位員工的同一段工時，不能同時計入兩個計畫的人事費。要確認投入比例相加 ≤ 100%。

### 其他可疊加的補助

| 補助 | 主管機關 | 是否可與 SITI 並行 |
|-----|---------|-----------------|
| 中央 SBIR | 經濟部 | ✅ 可（不重複核銷）|
| 北市就業獎勵補貼（薪資/租金）| 台北市產發局 | ✅ 可（不同計畫）|
| 新創天使稅額扣抵 | 財政部 | ✅ 可（不同性質）|
| NSTC 主題研究計畫 | 國科會 | ✅ 可（但目標客群不同，需說明）|
| 業界能專計畫 | 教育部 | ✅ 可（需有學校合作）|

## 第六章：常見情境決策樹

```
情境 A：「我是新創，設立 6 個月，要做 AI SaaS，該申請哪個？」
  → 創業補助（100萬）+ 同步準備研發補助計畫書
  → 創業補助計畫聚焦：MVP 開發 + 前 10 個台北市客戶

情境 B：「我設立 2 年，已有產品和客戶，想申請研發補助，應該申請多少？」
  → 創新研發補助，不要保守
  → 試算：人力 × 期間 + 工具費 → 得到「實際需要金額」的 50%
  → 多數人應該申請 300-400 萬（比平均 198 萬高很多）

情境 C：「我有好產品，但完全沒有品牌，要先做研發還是品牌？」
  → 如果產品還不夠完整：先研發（500萬）→ 結案 → 接品牌（500萬）
  → 如果產品已成熟但沒市場：直接品牌補助（500萬）

情境 D：「我們的技術和這次主題式研發的主題只有 60% 相關，值得申請嗎？」
  → 如果計畫書可以真實地以主題為中心，60% 夠了
  → 如果只是表面掛主題，不建議：通過率低，且佔用一次申請機會

情境 E：「我已有 Series A 創投，近 3 年獲投超過 500 萬，等新創拔尖還是先做研發？」
  → 先確認：創投願意寫推薦書嗎？（這是最硬的門檻）
  → 願意 → 等新創拔尖梯次（1,500萬，值得等）
  → 不願意 → 先申請創新研發（500萬，現在就可以）
  → 注意：新創拔尖結案後可再申請研發，兩者不互斥

情境 F：「我公司剛在台北市新租了辦公室，有什麼可以立刻申請的？」
  → 獎勵補貼（租金補貼最高 500萬，5年，50%）
  → 如果同時新增員工：薪資補貼（每人每月最高 1萬，1年）
  → 這兩個是「事後申請型」，租了辦公室就可以申請
  → 同時規劃主力研發/創業補助，不互斥
```
